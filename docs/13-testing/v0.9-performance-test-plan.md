1. Freeze a sanitized deterministic dataset manifest (SHA-256), two tenant fixtures,
   allowed targets, provider/model versions and reference SHA before measuring.
   Authenticated write scenarios use isolated test credentials via environment variables.
2. Record complete SHA, UTC time, host/node resources, dependency/config/topology hashes,
   thresholds and all rounds. External-provider runs record model/version, quotas, input/output
   sizes and cost bounds separately; deterministic runs do not establish model quality.
3. Count timeout/cancel/content/auth/cleanup failures; zero samples or missing reference,
   required metric, fault action or recovery window means INCOMPLETE and nonzero exit.
   Schema-valid JSON alone never makes an experiment PASS. Do not average percentiles.
4. Run migrations and concurrency/failure cases against real dependencies, then Compose
   and HA deployment. Inspect actual step logs: a skipped end-to-end step is not a pass.
5. Perform faults only in the isolated topology with a verified recovery point; record
   start/fault/recovery timestamps and raw counts, reconcile MySQL/objects/vectors/search.
   Stop on integrity, permissions or unexpected provider-side effects; preserve diagnostics.
6. Attach versioned results, profiles, topology manifests, sanitized logs, dashboards/alerts,
   backup/restore evidence and security/compatibility decisions to the candidate. Every row
   is required; absent infrastructure means Pending, not waived or implicitly successful.

Long stability runs use bounded batches under the CLI per-run limits, aggregate raw
histograms/counts without retaining bodies, and account for every batch and transition.
Failure runs report their own expected outage window rather than masking it in steady-state
success statistics. All thresholds must be accepted before implementation/execution.

## Automated Tests

`python/tests/test_performance_benchmark.py` uses deterministic response doubles
and a local loopback HTTP fixture. It covers URL validation, private-network
opt-in, all parameter bounds, pinned transport, parallel execution, JSON
contract, status classification, timeout, connection failure, HTTP error status
retention, the versioned result schema, and the P99 pass/fail gate.
The suite collects 25 pytest cases after parameterized boundary expansion.
On Python 3.12.14 the focused suite passed all 25 cases and recorded 86% total
coverage (`run_benchmark.py` 85%, `local_fixture.py` 92%).
The same tests, coverage gate, Ruff formatting/lint, and strict Mypy passed in
[pre-PR CI run 34686830287](https://github.com/CoderDongHuang/OpenEIP/actions/runs/34686830287).

Run the focused suite with:

```bash
cd python
pytest tests/test_performance_benchmark.py --no-cov
```

The same focused command is a required CI step. It must pass independently of
coverage instrumentation because the benchmark contract is a release gate.

The focused module coverage gate is run in CI with:

```bash
python -m coverage run --source=../benchmark -m pytest tests/test_performance_benchmark.py --no-cov
python -m coverage report --fail-under=80
```

Ruff formatting/lint and strict Mypy explicitly include `benchmark/`; the
standard Python working-directory checks alone do not cover this top-level
module.

## Local Baseline Procedure

Start the repository's deterministic fixture, then explicitly opt in to the
private target:

```bash
python3 benchmark/local_fixture.py --host 127.0.0.1 --port 8000
```

In a second terminal run:

```bash
./benchmark/run-benchmark.sh http://127.0.0.1:8000/health docs/13-testing/results/v0.9-performance-baseline.json \
  --allow-private-network --requests 200 --concurrency 4 --warmups 10 --timeout 2 --max-p99-ms 100
```

The resulting JSON must be reviewed with the commit SHA, service version,
hardware, fixture configuration, and timestamp. A failed request makes the
result `FAIL` and must be investigated before release.

The merged-main evidence is bound to commit `993569a`: 200/200 successful
requests, four-way concurrency, zero errors, and P99 34.292 ms against a 100 ms
threshold on Python 3.12.14. All six main-branch CI jobs passed in
[run 34688340556](https://github.com/CoderDongHuang/OpenEIP/actions/runs/34688340556).

## Release Evidence

This GET harness is control-plane evidence only. The complete v0.9 scope requires HA,
automatic scaling, measured capacity, multi-node recovery and fault-resilience
tests against the intended deployment topology before acceptance. Attach those
results to the release checklist; none are established by this fixture.

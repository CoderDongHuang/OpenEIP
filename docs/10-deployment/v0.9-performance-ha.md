# v0.9 高可用、扩容、调优与恢复部署设计

> Proposed，2026-10-26；不是已提供的部署产物或已通过的故障实验。
> 实施受 RFC-0012、ADR-0021 和编码前架构审查约束。

## 应用拓扑与资源预算

最小验收集群三个 worker，分散到不同节点；验证基础设施故障域与真实目标一致。
Ingress 至少两副本并有可切换入口，Java/Python 各三副本、Frontend 两副本。
Kubernetes 配置进入 `deploy/kubernetes/`，监控进入 `deploy/monitoring/`，
镜像使用最终候选的不可变 digest；不得使用未构建的版本号或 `latest`。

| 配置 | Java | Python | Frontend |
|---|---|---|---|
| requests / limits（初始待测） | CPU 500m/2，RAM 1Gi/2Gi | CPU 500m/2，RAM 512Mi/2Gi | CPU 100m/500m，RAM 64Mi/256Mi |
| replicas / HPA | 3，min3/max6 | 3，min3/max6 | 2，不自动伸缩 |
| HPA v2 | CPU 70%，scale-down stabilization 300s | CPU 70%，scale-down stabilization 300s | 不适用 |
| PDB | minAvailable2 | minAvailable2 | minAvailable1 |
| rollout | maxUnavailable0/maxSurge1 | maxUnavailable0/maxSurge1 | maxUnavailable0/maxSurge1 |
| scheduling | topology spread maxSkew1，按 hostname，DoNotSchedule | 同左 | 同左 |
| shutdown | readiness false、drain30s、grace45s | 同左 | grace30s |

HPA 依赖 metrics-server；没有可用指标不算扩容测试成功。CPU 伸缩只代表本次基线，
I/O/排队瓶颈需结合队列与依赖指标解释，不能无限加副本。限制每个增长周期的副本增长，
负载前校验节点余量、Pod quota、存储和数据库连接额度；初始参数通过调优报告才能接受。

## Secret、共享文件与启动预检

RSA JWT 公私钥、内部 token、Agent capability secret、Governance 加密 key、
Redis ACL/数据库/检索凭据从已有 Secret 引用，所有副本一致；禁止默认开发值与临时密钥。
Secret 文件只读且不进入报告或配置样例。备份密钥轮换前确认解密与 token 兼容路径。

Document 使用同一个 HA RWX 卷，必须验证多节点可见、CREATE_NEW/原子创建、路径约束、
权限、内容哈希与故障后读写一致；节点本地卷/普通 RWO 不满足多副本文件承诺。
迁移前对本地卷与元数据做一致备份，按对象 key/大小/hash 复制校验，再在写入暂停窗口切换，
验证全部对象可读后开放写入。保留旧数据供回滚；不能直接丢弃或空挂载本地数据。

多副本模式启动预检拒绝：临时 RSA/默认 secret、memory 检索、进程内限流/去重、
非共享文件后端、不可用关键依赖。Python readiness 实测 Redis/ES/Milvus；Java readiness
实测 MySQL/共享状态/文件依赖。liveness 不探测外部数据服务，避免依赖故障导致全体重启。

## 数据层 HA 与恢复验收

允许使用运维提供的托管集群或版本固定的官方部署，均须提交配置、版本/拓扑、故障过程、
恢复与数据验证结果。当前默认 Compose 的单节点配置不能算这些项已完成。
不引入新的数据服务产品；Neo4j 当前不在实际依赖面，启用前另行设计验收。

| 组件 | SAD 对应部署 | 最低验证 |
|---|---|---|
| MySQL | Group Replication/InnoDB Cluster 或 HA RDS，稳定 writer endpoint | writer 故障/切换、事务回滚、租约 fencing、已确认业务记录零丢失、备份恢复 |
| Redis | Sentinel 三投票节点 + 主/副本，或 Cluster | 主故障、重新发现、ACL/TLS、限流完整窗口屏障、缓存丢失重算；不假定异步复制零丢失 |
| Kafka | 三 broker，业务 topic replication-factor3、minISR2，producer acks=all | 单 broker 故障、outbox 重发、eventId 去重、积压恢复与 DLQ |
| Elasticsearch | 至少三节点，副本数≥1 | 丢失一节点后副本可读、写恢复、租户/文档范围一致性及快照恢复 |
| Milvus | distributed proxy/data/index/coordinator；etcd 三成员；底层对象存储 HA | proxy/worker/coordinator 故障、索引查询恢复、etcd quorum、从原文重建与 ES 对账 |
| MinIO | 四节点分布式纠删码，独立故障域，TLS/凭据管理 | 单节点故障、对象 checksum、恢复；不能用 standalone 代替 |
| RWX 文件 | HA 存储服务，跨节点 coherent POSIX 语义 | 断开一存储路径/节点、多副本读写、备份/恢复后所有对象 checksum |

提议验收目标：单应用 Pod/worker 故障 RTO≤60s、已确认持久业务数据 RPO=0；
数据服务自动切换 RTO≤120s、已确认 MySQL 业务数据 RPO=0；检索派生数据允许有界重建，
完整性验证前不得称恢复成功。灾备独立恢复目标 RTO≤30min、备份业务 RPO≤15min。
若测试环境/备份策略无法满足，记录失败并调整设计重新审查，不把“托管”当作自动达标。

## 网络、监控与调优

仅 Ingress 暴露业务入口，TLS 与受信代理链明确；AI internal、management、Redis/数据库和
检索服务不公开。NetworkPolicy 默认拒绝，仅允许必需服务与监控流量；关闭默认 ServiceAccount token，
应用非 root、最小权限，文件写仅限挂载目录。

Prometheus 抓取 Java/Python 与基础设施；Grafana 仪表盘/数据源 provisioning 版本化，
OTel collector 关联跨运行时 trace。告警至少覆盖：错误率>1% 持续5min、readiness 副本不足、
队列拒绝、连接池饱和、HPA 达 max、租约失效、恢复超时、存储空间、备份过期。
告警在测试环境注入故障演练，记录 firing/resolved；不能只提交 YAML。

调优报告保留：硬件/镜像/模型与依赖版本、数据集摘要、基线/候选 SHA、池/线程/队列/索引配置、
三轮结果、CPU/内存/GC/磁盘/依赖指标、瓶颈证据及回退配置。
修改池大小前按 maxReplicas 计算连接总预算；增加副本不能掩盖 DB/Redis/索引瓶颈。

## 扩缩容、故障、长稳与对账步骤

1. 独立 namespace 部署候选并验证固定数据、业务权限、配置/Secret 一致和三副本 ready。
2. 固定混合负载基线15min，再升载驱动 HPA 3→6；新副本 ready 前不计服务容量。
   降载后验证缩回3、无重复副作用/文件丢失/租户隔离退化，完整采集吞吐和资源。
3. 分别终止一个 Java/Python Pod、排空一个 worker、滚动替换应用；检查 RTO、token、
   上传文件、业务状态、outbox/inbox、SSE 取消。故障操作前验证 namespace 和资源归属。
4. 按数据层表逐组件故障，不同时破坏 quorum；采集故障前/中/后业务成功率与恢复过程。
5. 运行24h稳定负载，成功率目标≥99.9%；后6h RSS/FD/连接中位数较前6h增长≤10%，队列有界。
   每小时校验任务/对象/检索一致性，故障实验独立统计而不从稳态分母隐藏失败；
   完成全部固定测试对象校验后才清理本轮数据。
6. 在新的恢复 namespace 还原数据库、对象、密钥/配置，验证权限/审计/对象 checksum；
   分别模拟 ES 或 Milvus 部分写失败，运行有界 tenant/document/version 对账修复并复验。
7. 保存原始计数、指标/trace 摘要、故障时间线、版本与结果。缺少数据就是 INCOMPLETE。

## 发布与回滚

候选验证需显式运行整栈步骤，修复目前仅 `release/` 分支或 tag 触发的遗漏。
先在临时隔离环境验证，后续 tag CI 再复验；不在真实 tag 失败后移动/删除或复用标签。
手动发布入口必须校验真实 tag，verify/checkout/build/镜像标签/Release 使用相同 SHA；
当前工作流尚未实现这一保证，修复前不得用 main + input tag 发布。

应用回退先暂停 HPA、新工作和调度，保留审计/业务与文件备份，缩回单副本再部署兼容镜像；
旧 Worker 完全停止后才能回滚新增租约表。跨文件后端回退必须校验新写入对象已同步，
否则继续读新存储或暂停写入，不能用旧空快照替代当前业务内容。

## 顺序与发布证据

- [ ] RFC-0012 新公开讨论至少一周，≥2/3 Maintainer 赞成并记录理由。
- [ ] ADR-0021 接受，完整设计通过编码前架构审查。
- [ ] SDD WP1～WP4 实现完成，全部测试矩阵有最终候选 SHA 和产物。
- [ ] 六项质量门禁全部通过，独立安全审查无阻断项。
- [ ] 完整实现 PR 至少一位正式 Approve，意见处理完成并合并 main。
- [ ] 最终候选整栈实际执行，不能只记录因条件跳过的绿色 job。
- [ ] 发布前备份/回滚演练通过，Release Notes 与真实能力一致。
- [ ] 在所有发布前置条件通过后创建新的不可变 tag；记录 tag 指向的完整 SHA。
- [ ] tag 触发的 verify、Java/Python/Frontend 镜像构建、扫描、digest 与 attestation 全部通过。
- [ ] GitHub Pre-release 和镜像下载/smoke 验证完成，记录链接。
- [ ] 发布失败保留失败 tag，不移动、删除或复用。

手动 release workflow 的输入 ref 尚未贯穿 checkout/verify/image；
修复并测试前，不得在 main 上仅输入另一个 tag 名称发布。真实 tag 路径也必须通过所有门禁。
